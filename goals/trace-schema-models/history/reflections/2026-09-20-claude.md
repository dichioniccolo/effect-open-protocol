# Reflection — trace-schema-models (2026-09-20, claude)

## Summary

The trace store's hand-rolled insert/select schema pairs became two
`Model.Class` models plus a read model, and the statements then moved out of the
service entirely: a derived `RunRepository` for the run insert, a query set for
everything no derivation expresses. Shipped as PR #11, rebase-merged to `main`
in four commits with `check`, `lint`, `format:check` and 158 tests green. The
implementation is materially better than the spec described, because two
quality reviews rejected the first two shapes.

## Tooling experience

- **Worked:** `.repos/effect` as the API authority was decisive — every real
  finding this session (FieldExcept, `.make` vs `.makeUnsafe`, the
  GeneratedByDb/update-variant conflict, the resolver dedup) came from reading
  source, and none would have come from recall. `bun run check` across four
  workspaces caught every rename call site in one pass, which is what made
  "break the exported names and fix them all" a safe strategy.
- **Didn't:** JSDoc examples are invisible to the build. A rename can leave
  every example in a package broken and ship green.
- **Frustrating:** `SqlSchema`'s `execute` receives the *encoded* request while
  the service's own signatures are decoded. Nothing in the types announces that
  boundary; it only surfaced as a type error after I had already shaped a module
  around the wrong assumption.
- **Wished existed:** a packet-level "the spec said X, the code now does Y"
  check. Three passes edited `SPEC.md` by hand to stay truthful, and only
  reviewer discipline kept the packet from describing code that no longer
  existed.

## Implementation improvement opportunities

- `WireStoreService` still restates six signatures that the query set and the
  repository already type. It is the package's public contract, so restating is
  defensible — but if the store ever grows, deriving it from the parts is worth
  revisiting.
- The recorder's queue is unbounded (`Recording.ts:67`). Batching keeps SQLite
  off the wire's critical path, but nothing pushes back if the writer falls
  behind; the failure mode is memory, not latency. Out of scope here, worth its
  own packet.
- `bun:sqlite` is synchronous, so each batch blocks the event loop for the
  length of its transaction. Dropping the needless `withTransaction` helped;
  the underlying stall is structural and unmeasured.

## Goal & prompt critique

- The `GOAL.md` scope list said "Out: … `SqlModel.makeRepository`". That was
  inherited from a decision whose premise was wrong (it rejected the repository
  for lacking a batch insert, when the real reason was that its insert is
  row-at-a-time). A launcher should carry the *reason* for a non-goal, not just
  the name, or a later session will honor a stale prohibition.
- The workflow section said "first slice: Run + RunSummary end to end … this
  settles the `Run.extend` variant-loss risk". That was the single most useful
  line in the packet: the risk was real, cheap to settle, and settling it first
  meant `TracedEvent` was built on a proven assumption. Keep that pattern —
  name the unproven assumption and the slice that resolves it.
- What the launcher lacked: any statement of what the *reader* of the resulting
  code should experience. Every subsequent round ("no raw SQL in services",
  "repository as its own service") was a quality requirement that the goal never
  expressed, so it arrived as rework rather than as scope.

## TODOs worth codifying

- A `check-jsdoc-examples` script wired into `bun run check`. Three ad-hoc
  extractors in one session is the signal.
- `SqlModel.makeResolvers` deduplicates equal request payloads — unusable for
  append-only inserts. This belongs next to the SQL guidance, not buried in a
  packet decision log.
- `Model.GeneratedByDb` omits the id from `update`; `makeRepository` requires it
  there. The documented shape for a primary key is
  `Model.Field({ select, update, json })`.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Read the implementation of any derivation before routing
  a hot path through it — `SqlModel.makeResolvers` would have deduplicated
  traced events and lost rows, and nothing about its name or signature says so.
  Behavior that only source reading reveals is exactly the behavior that ships
  as a silent data bug.
- **HIGH — Critical:** When a refactor relocates code, relocate the whole
  concept. Splitting a query across two files cost an encoded-type leak, an
  `unknown` return and a reviewer round; moving the whole thing deleted all
  three at once.
- **MEDIUM — Best practice:** Derive types from constructors rather than
  restating them. The hand-written repository interface drifted within one
  commit of being written.
- **MEDIUM — Best practice:** Write acceptance criteria as invariants a command
  can check. "Byte-identical SQL" did not survive contact with the work;
  "no statement text in the service" did.
- **LOW — Consideration:** When a packet's quality bar lives only in the
  reviewer's head, it surfaces as rework. If the code will face a strict review,
  say so in the spec so the first implementation aims there.

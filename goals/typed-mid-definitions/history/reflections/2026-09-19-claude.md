# Reflection — typed-mid-definitions (2026-09-19, claude)

## Summary

Open Protocol MIDs are now defined as data: `Field` turns fixed-width wire
fields into Schemas, `Mid.define`/`Mid.request` give each revision its own
exact type and each request its declared reply, and every built-in MID runs
through the same path. Typed `request` returns exactly the declared reply,
with `UnexpectedRevision` and `PayloadEncodeError` as new typed failures. A
body that does not decode no longer costs the session. PR 7 is mergeable
(CLEAN, no threads); 128 tests, lint, format, check and build are green.

## Tooling experience

- **Worked:**
  - `expectTypeOf` in `@effect/vitest` pinned the exact types (per
    revision, per reply, `@ts-expect-error` for undeclared revisions), which
    made the riskiest part of the design testable before any migration.
  - Reading Effect v4 source in `.repos/effect` settled several design
    questions quickly: `SchemaTransformation.transformEffect`,
    `SchemaIssue.InvalidValue`, `ParseOptions` being closed, and
    `Schema.makeEffect`.
  - The anti-slop lint rules caught real issues:
    - manual `_tag` objects, which became `Data.TaggedClass`;
    - chained casts, replaced with overloads;
    - a scoped helper that belonged at module level.
- **Didn't:**
  - The spec PDF could not be read (no text extraction, no page rendering).
  - A Python edit script that failed mid-way left nothing written, which was
    correct but cost a round trip.
  - `bun run format` rewrapped code between an edit and the next scripted
    replacement, so a string match missed.
- **Frustrating:**
  - A generic method can't be instantiated in a type position, so reply
    types had to be pinned through `ReplyOf` and runtime values instead of
    `DeviceConnectionService["request"]<Rev>`.
- **Wished existed:**
  - A doc-example type-check script.
  - CI.
  - A local text copy (or page index) of the specification's MID tables.

## Implementation improvement opportunities

- **One remaining type assertion.** `RequestReply.request` narrows the reply
  to `ReplyOf<Rev>` with a SAFETY comment. A typed per-request Deferred would
  remove it.
- **Linear registry lookups.** `builtIns` lookups are linear; build a
  MID/tag index once. This matters more when `typed-subscriptions` adds a
  registry of user definitions.
- **Sync encode throws.** `encodeMessage` still throws a `PayloadEncodeError`
  as a defect when a built-in value does not fit its fields. Today only an
  out-of-range torque in a 0061/0065 can trigger it, since the classes
  validate everything else. A `Result`-returning variant for callers that
  build results from untrusted numbers would be safer.
- **0061 parameter 21.** It is written with the tightening timestamp, as the
  old encoder did, but it means "last change of the parameter set". If a
  consumer ever needs it, model it.

## Goal & prompt critique

- **Allow merging a de-risk phase.** PLAN.md should say that a phase whose
  only purpose is de-risking may merge into the next once a type test proves
  the design. P1 and P2 merged here, and the plan had to be amended after the
  fact.
- **Constrain the property, not the assertion text.** The SPEC constraint
  "round trips pass without their assertions changing" should read "the
  round-trip property holds unchanged". Making the codec effectful was in
  scope, and the test form had to change with it.
- **Name the fallback when the spec is unreadable.** GOAL.md was clear and
  small enough. One addition: "if the specification cannot be read, use an
  illustrative MID and say so in the PR". The SPEC already allowed this, but
  the launcher did not point to it.

## Lessons (confidence-tiered)

- **HIGH — Critical:**
  - **Prove type-level designs with `expectTypeOf` before migrating
    callers.** The exact per-revision and reply types were the whole point
    of this goal, and pinning them first made every later step mechanical.
  - **Keep framing/header errors fatal and body errors recoverable.** A
    controller answering at a newer revision would otherwise reconnect-loop.
    The split is now covered by `Session.test.ts`.
- **MEDIUM — Best practice:** Carry out-of-band decode context (the device
  id) through a `Context.Service` read by the Schema transformation, not by
  threading parameters through every codec. It keeps codecs as plain Schemas
  and lets user-defined MIDs ignore it.
- **LOW — Consideration:** Built-in definitions are named `<Message>Mid`
  because the classes keep their names. If the class/definition pairing
  keeps growing, consider attaching the definition to the class as a static.

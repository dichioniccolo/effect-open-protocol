# Reflection — wire-trace-ui (2026-09-18, claude)

## Summary

Both CLIs now record every traced chunk and frame into a shared SQLite file, and
a Next.js app on Bun browses the runs, filters them, decodes headers and tails
them live. All nine phases ran in order. The P1 gate passed, so the fallback
topology was never needed, and the work shipped as PR #3, `mergeStateStatus:
CLEAN`. The verdict is that it did what was asked, with two contract
adjustments forced by how Next on Bun behaves.

## Tooling experience

- **Worked:** Reading Effect v4 source in `.repos/effect` instead of guessing
  settled every atom, SQL, SSE and Queue question on the first try (for example,
  `BEGIN IMMEDIATE` in the Bun SQLite client making concurrent migrations
  safe). Next's version-matched docs in `node_modules/next/dist/docs/` answered
  the async `params` question. Headless Chromium from the Playwright cache
  turned "looks right" into counted rows and console-error checks.
- **Didn't:** `tsc` accepted `WireStore.asEffect()`, which does not exist at
  runtime. Next's conflict error named `transpilePackages` although the config
  never set it. `pkill -f` killed its own shell twice.
- **Frustrating:** The SSE leak was invisible to every check the repo has. It
  took a temporary log line to prove that nothing ended the poll loop.
- **Wished existed:** An example compiler (again), and a committed UI smoke
  test.

## Implementation improvement opportunities

- Window the packet table and move filtering to `EventQuery` so long runs stay
  cheap.
- Give the library a source export condition so `store/` stops reaching into
  `src/` by relative path.
- The detail pane keeps showing a selected packet after filters hide it, which
  is defensible but worth a visual cue.
- A run killed with SIGKILL never gets `endedAt`. The run list labels it "no
  end stamp" after 30 s of silence, but the store itself cannot tell a dead run
  from a quiet one.

## Goal & prompt critique

The gate-first sequencing was the best part of the packet and should stay the
template. One edit would help: acceptance criteria should state outcomes
("the first page appears without a client fetch") rather than mechanisms
("hydrated"). Mechanisms belong in the decision log, where this packet ended up
recording them anyway.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Prove cleanup paths by observation, not by reading the
  code. The abort-signal wiring was correct and still never ran; only counting
  polls after a disconnect showed it.
- **HIGH — Critical:** Put the architecture-deciding unknown in a gate phase
  with its fallback pre-chosen. It cost minutes and removed the biggest risk
  before any dependent code existed.
- **MEDIUM — Best practice:** When a `Context.Service` helper type-checks but
  is untested, run it once. Effect v4 RC typings and runtime can disagree.
- **LOW — Consideration:** SSE with a bounded lifetime and `Last-Event-ID`
  resumption is a robust default even where disconnects are reported. It
  bounds every failure mode for the price of one reconnect every 20 s.

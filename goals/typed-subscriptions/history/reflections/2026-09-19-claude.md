# Reflection — typed-subscriptions (2026-09-19, claude)

## Summary

`connection.subscribe(Sub.rev(n))` returns `Stream<{ value, ack }>`, typed
exactly, restored after every handshake and kept alive across reconnects.
Tightening results now run on `subscribe(LastResults)`. The Delivery, Chaos,
GapRecovery, Shutdown and ResultDelivery suites passed with their files
untouched. It shipped as PR #8, which is `CLEAN` with zero unresolved threads.
The existing suite passed on the first full run after the rewire, which says
the P1-before-P3 sequencing and the guarded suites did their job.

## Tooling experience

- **Worked:** `.repos/effect` for checking `Queue.shutdown`/`end`, `Stream.unwrap`
  and `forkChild` semantics before relying on them. `tsc` with a
  `@ts-expect-error` to prove the "bare control MID" check rejects a field-carrying
  ack. Removing the directive showed the expected error. `oxlint` anti-slop
  spacing caught test layout issues fast.
- **Didn't:** nothing type-checks JSDoc examples, and two shipped examples were
  broken.
- **Frustrating:** the JSDoc rubric forbids `declare` in examples while most
  existing examples use it.
- **Wished existed:** a `check:examples` script, and a simulator hook for custom
  pushed MIDs. Tests had to hand-roll a scripted controller, which is in scope
  as test code but duplicates the one in the request example.

## Implementation improvement opportunities

- ResultDelivery acks through `subscriptions.acknowledge` rather than each
  element's `ack` (see findings).
- Refusal while restoring at the handshake ends the session for any
  subscription. That is fine for MID 0060, but it loops for an unsupported
  custom MID.
- Restoring subscriptions one after another while holding the gate means a
  subscription with a full queue can block the read loop and time out a later
  subscribe. This is the same class as today's backpressure, but it is worth a
  test.
- `subscribeResults` stays exported but unused in the library. Deprecate it
  in a later API pass.

## Goal & prompt critique

- The SPEC should have named the gap-recovery lifetime hazard (see findings).
  It was the only non-obvious correctness trap in P3.
- GOAL.md should say what to do when the prerequisite is merged but this
  packet is still `paused`.
- "`subscribe(LastResults)`" in the spec left the naming open. `LastResults`
  worked, but writing out the definition's shape (`Mid.subscription(data,
  { n: { subscribe, ack?, unsubscribe? } })`, mirroring `Mid.request`) would
  have saved design time.

## TODOs worth codifying

- Example type-check script in `bun run check`.
- JSDoc `declare` rule reconciliation.
- Handshake-refusal policy and test for custom subscriptions.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Tie background work that a session triggers to that
  session's lifetime. A forked `recoverGap` that outlives its session holds the
  single-pass flag and silently skips the next session's recovery.
- **HIGH — Critical:** Register built-in subscriptions synchronously at
  construction (`open` in the connection scope), not lazily when a forked
  consumer first pulls. Otherwise the first handshake races the registration.
- **MEDIUM — Best practice:** In the frame dispatch path, remove registry
  entries and shut down their queues outside the gate. A read loop blocked on
  a full queue must be released before anything waits for a reply.
- **LOW — Consideration:** Mirror an existing constructor's shape (`Mid.request`
  → `Mid.subscription`). The typing patterns, including the overload-compatibility
  workaround of returning `Omit<Untyped, "lookup">`, carried over directly.
